# Layout

Where the code lives, folder by folder. `AGENTS.md` holds the rules and the build commands.

| Path | Holds |
|---|---|
| `app/` | The frontend: React + TypeScript + Vite (pnpm, Node pinned in `.node-version`). Builds to `app/dist`, which the app ships. `views/` (library, clip detail, import sheet, settings, `Gear/` with its slots for later Gear packages: `segments.tsx`, `pages.tsx`, `slots.ts`, `DeviceLists.tsx` the Connected and Devices pages, `Overview.tsx` a device's Overview, `SaveDevice.tsx` the name and aircraft sheet, `Gear/Osd/` the FC page's OSD segment, `Gear/Rates/` the Rates segment (curves, compare, the sims' rates, `RateEditor` and the sims' Sync), `Gear/Switches/` the Switches segment and the Controls page, `Gear/Setup/` the radio's Setup segment (`useSetup` saves through `gear_radio_setup_edit`, `CopyDialog` Copy from; `lib/setup.ts` its pure helpers and Learn), `Gear/Sim/` the Sim page (`SimHub` its sections; Fly: `SimPage`, `Stage`, `scene.ts` the three.js picture, `Osd`, `SimSettings`, hidden unless the `simPreview` setting is on; Radio: `CalibrationPage`, the sim's calibration; Rates: `Gear/Sims/`; Profiles: `ProfilesPage`, the fit from a quad's logs and the fitted profiles, mock `ipc/mock/simfit.ts`); `lib/simhost.ts` the host loop (clock sync, interpolation, frame stats) and `lib/simview.ts` its pure helpers, `Gear/Backups/` the Backups segment, `Gear/Models/` the radio's Models and Checklists segments (`useModel` stages ops through `gear_model_edit`; `lib/models.ts` its pure helpers), `Gear/RadioSettings/` the radio's Settings segment (`radio.yml`; `useRadioSettings` stages ops through `gear_radio_settings_edit`; `lib/radioSettings.ts` its pure helpers), `Gear/Voice/` the Voices page (`VoicesPage` the pack library, `ApplyToRadios`, `DeletePack`, `SpeechCheck` a pack's speech check sheet (lines to review first, play, Accept, Re-take selected priced by a dry run), `Studio` the ElevenLabs voice studio, `useStudio` its data, `BrowseVoices` the Voice Library sheet, `Gallery` the Samples gallery (cards by voice, `FlagControl`), `useGallery` its data, `usePlayer` its player (Play all, Stop), `Publish` the publish review with Approve) and the radio's Voice segment (`VoiceSegment`), `Gear/Apply/` the apply sheet, `Gear/Changes/` the Changes segment (`ChangeTable` the change table the Bench shares, history, Edit setting, Copy settings), `Gear/Bench/` the Bench page and the copy dialog (`lib/bench.ts` its pure logic), `Gear/Storage/` the Storage page and `Gear/Flights/` the Pack up, Flights, Packs and Repairs pages; `Shell/StatusBar.tsx`, the Gear status bar), `components/` (`PathText` every displayed file path, with `dash/`, the dashboard pieces every page builds on: `PageHeader` (title, subtitle, actions, `fold` buttons that join the `…` menu when narrow, `more`), `SummaryLine` (a page's counts under the title), `StatRow`/`Stat` summary tiles, `DataTable` (columns, checkbox rows, group rows, numeric columns, stacked rows when narrow), `SectionCard`, `Disclosure` (a closed part of a page), `WithDrawer`/`DetailDrawer` (a row's detail on the right; a sheet when narrow), `Badge`, `EmptyState`, `FactList`, `StatusDot`, `MoreMenu` (the `…` menu, or a pop-up button with `text`); `trim/`, the one trim editor, used by clip detail and the import review, and `gear/`: `DeviceHeader`, `PlugInBar`, `ChecksList`, `DiffView`, `Sticks` (the two-stick widget, Mode 1-4)), `store/`, `actions/`, `ipc/`. Icons and fonts are inlined or bundled so the app works offline |
| `src-tauri/src/` | Rust core. `core/` (`Core`) owns the session and the library index and is the one surface every front end drives: `mod.rs` (state, locking, `Hooks`), `import.rs` (stage, analyse, dates, import, verify, delete clips after import, format), `staging.rs` (staging folders: the `.owners` list, the replaced session's folder, the sweep), `library.rs` (the index, list, rate, edit, rename, redate), `cuts.rs` (session and library cut lists), `files.rs` (Photos, previews, strips, Trash), `rematch.rs` (radio logs matched again to library clips), `prep.rs` (card prep: format a card with no session) and `setup.rs` (settings, places, profiles) and `gear.rs` (Gear: devices, detection poll, on-connect hooks, cues). `api/` is the one method table: each row names a method, its params and result types and the `Core` call, and `api!` makes `Core::dispatch` (socket, MCP) and one typed Tauri command per method from it; `api/events.rs` holds the typed events; `api/gear.rs` holds Gear's rows, which join the table through `with_gear_rows!`. `lib.rs` holds the GUI's own Tauri commands and `specta_builder`, which tauri-specta exports to `app/src/bindings.ts`; `control.rs` the app's socket, `updater.rs` the app's own updates (tauri-plugin-updater: the launch and hourly check, download, install and restart, as GUI commands only; the restart's new process comes to the front (the `update-relaunch` mark in the cache folder, never with `QUADCAM_NO_FOCUS`); `core/update.rs` holds the state for `status.update` and `restart_blocker`, which refuses the restart while a job runs), `mcp/` the MCP server (`server.rs` the protocol, the stdio loop and handlers, `reload.rs` the switch to a newer build on disk (`exec` in the same process, the handoff, the probe), `params.rs` each tool's argument type, `tools.rs` the tool list with schemas derived from those types, `render.rs` the text answers, `gear.rs` the three Gear tools with their argument types and handlers), `bin/quadcam-cli/main.rs` the CLI (clap flags build the `api` params, and it calls the table's `api::call` functions; `bin/quadcam-cli/gear/` holds the `gear` subcommands, one file per area). `gear/` is Gear (`docs/gear-design.md`): `model` (shared types), `store` (the gear folder and `gear.json`, its only writer), `compat` (proven versions), `serial` (USB serial ports, the per-port lock, the check for another process holding the port, the fail-safe), `detect` (what is plugged in), `events` (connected, identified, unmounted but present, removed), `cues` (speech, sound, notification; a voice pack's clip per cue line, `Core::cue_pack` picks the pack), `bf/` (the Betaflight link: `cli` the CLI session and the write engine `run_lines`, `msp` v1/v2 framing and identity, `blackbox` the blackbox flash over MSP (summary, chunked read, erase and poll, log header reader, estimates), `dump` the `dump all`/`diff all` parser with section context, `verify_lines` and the transcript scrubber, `fake` the `FakeFc` simulator, `boards` known issues, USB limits and the makers' build sources per board; `core/fc.rs` holds its `Core` jobs, each opening and releasing the port with one cue), `flights/` (flight analysis from radio logs: armed runs, hover, sag, resting voltage, mAh, dropouts, the `flights.json` cache; `synth` the synthetic log with known values), `packs` (packs, pack types, flight sets, pack history, suggestions), `blackbox` (pulled flash images: one record per pull under `<gear>/blackbox/`, the raw image in the blob store, the by-order pairing of logs with flights; `core/blackbox.rs` holds the pull job, the flash summary (one MSP read, no cue), the USB disk path, the manual erase and the `blackbox` on-connect step, `bin/quadcam-cli/gear/blackbox.rs` its CLI, `app/src/views/Gear/Blackbox/` its FC segment), `crashes` (the crash and repair log), `report` (the session report), `preflight` (the Pack up check; `core/flights.rs` holds their `Core` methods, `mcp/gear_flights.rs` their MCP actions, `bin/quadcam-cli/gear/flights.rs` and `packs.rs` their CLI), `osd` (Betaflight OSD positions: decode, element table, grids, per-profile render, overlap and off-screen check, the editor's `OsdMove`/`OsdCopy` resolve and `apply_edits`; `core/osd.rs` holds `Core::gear_osd` and `Core::gear_osd_edit`), `rates` (rate profiles of a dump, curve samples, the fit of one rate model onto another; the math is `quadcam_sim::rates`), `sims/` (one adapter per sim: Liftoff, Micro Drones, Uncrashed, The Zone, Velocidrone off; byte-span `Doc`, `Slot`/`encode`/`write_profile` for writes; `core/rates.rs` holds `gear_rates`, `gear_sims` and `gear_rates_preview`; `apply/sim.rs` the sim sync plan and `core/sim_sync.rs` its plan, apply and rollback, `core/sim_restore.rs` the restore of a sim's backup), `blobs` (the content-addressed blob store), `changes` (staged changes under `<gear>/changes/`, `render_fc`: FC edits to CLI lines, diff and before state), `apply` (`apply.rs` the report types, `apply/fc.rs` the FC plan, its checks and digest, `apply/card.rs` the card plan, its checks and digest, `roll_back` and `verify`; `core/apply.rs` stage, plan and apply as one FC job; `core/apply_card.rs` the card apply and the mount cycle (`Env.mount` and `Env.unmount`: a card is mounted for a job and unmounted after, the person's Mount lasts 10 minutes); the sheet's click is `gear_apply_click`, an agent's request waits on `Hooks::confirm_apply`; `core/action_ask.rs` puts card repair, a blackbox pull that erases, blackbox erase and the volume rename through the same sheet, with `_click` methods for the app's own buttons), `copy` (copy settings between quads: pure, over two `dump all` texts; `core/bench.rs` holds Keep, Revert, the copy rows and the `apply_ready` on-connect step), `backup` (snapshots: take, read, diff, retain, prune, export, import old backup folders; `core/backup.rs` holds its `Core` jobs and the on-connect `backup_hooks`), `radiologs` (each radio log once per radio), `health` (the card check: `diskutil verifyVolume`/`repairVolume` through `DiskRunner`, its log), `splash` (an image as the EdgeTX splash: 1-bit 128x64, preview, patch and decode a firmware image by its markers), `radios/` (one profile per EdgeTX radio board, `boards.rs` the rows, about 50, all but the proven ones read-only: chip, firmware format and size guard, DFU and bootloader entry with the DFU steps the UI shows, storage and write route, measured USB speed, SD-card pack, YAML schema, splash kind, internal ELRS targets and upload methods, USB product name and ports, last EdgeTX series, look-alike boards, target history, the maker's fork, switch and pot slots, quirks; `check_flash` its guards; the flash, read, restore, DFU link, ELRS flash plan and detection (`Connected.radio`) read it), `elrs/` (ExpressLRS, a preview behind `elrsPreview`, `docs/gear.md`: `crsf` the CRSF codec and parameter messages, `link` the passthrough through a radio's CLI or an FC's CLI and the CRSF conversation, `fake` `FakeElrs`/`FakeHost`, `image` the release bundle, targets and the options block of an image, `flash` the target guard and the `esptool` arguments, `uid` the binding phrase's UID; `core/elrs.rs` holds its `Core` jobs: read, the staged `Edit::ElrsOptions` plan and apply, and the flash plan and apply), `dfu` (USB DFU 1.1 with DfuSe over a `Usb` transport: `NusbUsb` real, `FakeDfu` in tests; erase, write, read back, leave), `firmware/` (`check` newest releases against the saved devices, `vendor` an FC's maker's builds (the Zendesk feed, each file's version line, build identity, the vendor or official channel), `edgetx` the release zip, the board binary and the image checks, `betaflight` the FC flash's board table, Intel HEX, image checks, build service (`Cloud`) and cache, `betaflight_config` the settings carried over a flash, `mod.rs` the `Flasher` trait with its recorder, `FwEnv` and `FixtureFetch`; `core/firmware.rs` holds the check, the splash preview, the flash plan and the flash apply (an FC's go to `core/bf_flash.rs`, a preview behind `bfFlashPreview`: backup, `bl`, DFU flash, then the old settings through the FC apply), each flash behind a digest and `confirm`, and a process started by cargo flashes only a fake unless `QUADCAM_FLASH=real`; `core/fw_restore.rs` lists a radio's firmware copies (`fwcopy`) and restores one through the same DFU write, `dfu_write`, behind a plan, a digest and `confirm`), `edgetx/` (the EdgeTX card engine: `yaml` the line-level editor, `model` typed views and `ModelOp`, `radio` the typed view of `radio.yml` for the Settings editor and the range check every `set_scalar` passes, `editors` the model editors' ops (value screens, logging, RSSI alarms, callouts owned by track name, timer and checklist checks) with their reads and the staged-op merge, `card` plans, the per-file writer and the unmount, `synth` the synthetic card, `cli` the radio's USB serial CLI (`RadioCli`, `FakeRadioCli`), `setup/` a radio setup as data (`docs/radio-design.md` 4.2 and 5: jobs, assignments, the template with `@job` tokens, aircraft overrides; `generate` its generator, `defaults`, `lua` QuadCam's own Lua screens, `postflash` the storage pack, ELRS Lua and volume label planners; `core/radio_setup.rs` holds its `Core` rows); `core/gear_card.rs` holds its `Core` reads and `gear_card_clean`, `core/radio_cli.rs` the serial jobs, `core/dfu_link.rs` the link of a DFU device to a saved radio, `core/model_edit.rs` `gear_model` and `gear_model_edit`, `core/radio_settings.rs` `gear_radio_settings` and `gear_radio_settings_edit`), `voice/` (radio voice: `lines` QuadCam's lines and the spelling rules from `resources/voice/`, `asr` the speech check's comparison (spelling, numbers as words, case and punctuation aside), `tts` the `say` and OpenAI-compatible providers behind `Tts`/`Run`/`Post`, `eleven` the ElevenLabs provider (models, voices, credits, the Voice Library and its add, speech with character timestamps, through `Http`), `keychain` the API key in the macOS Keychain behind `KeyStore`, `rates` the one rate table (USD per 1K characters, promo, request limit) and the recorded character counts, `batch` carrier-sentence batches cut by those timestamps with their cache, checks and estimate, `reuse` the line index (a line a cached take holds is cut from it, never sent again; per-voice counts; the import of earlier single-line takes), `sets` the line sets in `resources/voice/sets/`, `render` the raw cache and normalisation, `packs` build, index and install, `publish` the voices repo (release names, previews, spot check, the license by provider, `gh` through `Gh`, the printed commands), `wav`; `core/voice.rs` holds its `Core` methods and `core/voice_publish.rs` a pack's publish (prepare and review as an `api` row; Approve, `voice_publish_approve`, is a GUI command and the CLI's `--approve` at a terminal, never MCP) and an index pack's previews, `core/voice_studio.rs` the studio's (key, catalogue, the Voice Library and its add, estimate, sample, set render of one or several packs with progress and Stop; never a paid call without `confirm` and a credit check); `core/voice_samples.rs` the sample gallery (samples in `<gear>/voice-samples/` with `samples.json`, moved once from the cache; the packs as cards; flags in `flags.json` beside the takes, marked in the line index as `rejected`; `gear_voice_retake`, the flagged takes again with a seed from the flags, priced and confirmed with its digest); `core/voice_check.rs` the speech check (`gear_voice_check`, and after every render and sample: a line heard wrong in a studio pack leaves it as a re-take, recorded per take in the line index as `heard`; `accept` puts it back; a named re-take line is heard again from its held take); `core/voice_groups.rs` the grouped re-take (`gear_voice_retake` with `grouped`, on a pack or a sample voice: lines grouped by the word they got wrong, one line per group tried other ways, the winner kept as a `Structure` for its lines in `pack.json` or `samples.json`; `voice_studio::adopt` carries a sample's structures into a pack render, and the estimate's `validation` reports the samples of the `sample` set, the risky lines); `Edit::CardFiles` applies through `core/apply_card.rs`), `switchmap` (the switch map: an EdgeTX model's mixes, logical switches and special functions joined with `aux`/`adjrange` per control and position, conflicts, live matching), `radio_hid` (the radio in USB Joystick mode over hidapi, `FakeHid`, the `radio-input` stream; `Hub`, the one reader for that stream and the sim's unthrottled sinks; `core/switchmap.rs` holds both `Core` reads and the watch), `sim_cal` (the sim's radio calibrations keyed by Gear radio id, the resolve step, the defaults from a switch map; `core/sim.rs` holds its `Core` rows and the calibration session; `sim_profiles` the profiles fitted from logs, one file each in `<gear>/sim/profiles/`; `core/sim_profiles.rs` the profile list, the fit (blackbox pulls, the latest backup, and the aircraft's radio logs paired as `gear_flights` pairs them, for pack resistance) and its save behind the fit's digest and `confirm`; `core/sim_host.rs` the in-process sim host: the physics thread, the input ring and the page's frame reads, as GUI commands only). The logic modules (`scan`, `disk`, `media`, `logs`, `logmatch` (shape-first log matching: flight lengths, order and gaps, clocks as tie-breaks, EdgeTX models as a filter; an analog clip with dead air matches by picture: flights inside keep ranges, swaps at dead air, short armed dead air as breakup, volt steps per cell, an offset per clip, split DVR files as one timeline), `moments`, `highlights` (macOS video analysis: `highlight` moments for clips without radio-log moments, the key frame, the `app.quadcam.video` item, the cache by content fingerprint; `core/video.rs` holds the session's background job and `library_analyze_video`), `join` (recordings an analog DVR split into files: detection, the `ffconcat` source, the swap of joined and own values), `metadata`, `qtmeta`, `naming`, `pipeline` (with `pipeline/import.rs`, the import run), `session`, `photos`, `library`, `trim`, `cuts` (the one cut writer), `sources` (the `Source` trait per video system, tried in `sources::all()` order; `sources/dji.rs` is DJI (an O4 air unit over USB, a goggles card, older `DJIG####` names): `DCIM/DJI_*/` names, the clock in the name, `.SRT` sidecars, byte-copy MP4 export, no "Format card" after an import, card prep (exFAT) for a removable goggles card only; `sources/analog.rs` is the DVR: clip layout, half-written check and repair, encode plan, dead air, card policy), `trash`, `settings` (with `Defaults`, the effective settings), `paths` (every path under `$HOME`), `geocode` (place search, and `reverse`: a point named by Apple's geocoder), `locate` (this Mac's location from Location Services, one fix), `sun` (sun tags from a clip's place and time, offline, in the place's IANA zone through chrono-tz; `metadata::zone_for`), `weather` (Open-Meteo's archive and historical forecast through `Fetch`, and `zone`, a saved place's time zone (`timezone=auto`), stored on the `Place` by `Core::place_zones` while the `weather` setting is on; `core/weather.rs` holds `library_weather`, which writes `app.quadcam.weather`)) run without Tauri |
| `src-tauri/sim/` | `quadcam-sim`, the sim core (`docs/sim-design.md`), a workspace member with no Tauri dependency: `input.rs` (samples, the input ring, calibration, auto-calibration, the link model); the physics and controller (`sim.rs` the step, `world.rs` Rapier, `motor`, `aero`, `battery`, `mixer`, `fc`, `rates`, `diff` its own `diff all` reader, `profile` with the presets in `presets/`, `ring` the frame each step reads, `runner` the real-time thread, `snapshot`, `record`, `bench`); `bbl.rs` QuadCam's own blackbox decoder (from the documented format; `blackbox_decode` is GPL and never used); `log.rs` and `validate.rs` the validation harness on blackbox logs (.bbl, flash images, decoded CSV), with fixtures in `tests/fixtures/`; `fit.rs` the profile fit, which keeps a fitted group only when the harness scores it no worse than its base; `LICENSES/` the notices of ported MIT code. The dev profile builds it and its physics crates optimised. Test it with `cargo test --workspace`; `cargo run -p quadcam-sim --example bench` is the 10 min real-time bench |
| `intel/` | `quadcam-intel`, the Swift helper (SwiftPM, `docs/development.md` "The Swift helper"): `caps`, `asr` (SpeechAnalyzer + SpeechTranscriber, macOS 26+), `install` (AssetInventory), `video` (`Video.swift`: MediaIntelligence VideoAnalyzer highlights, levels and key frame, macOS 27+), `suggest` (`Names.swift`: Foundation Models clip names, keywords, notes and a day's summary; text on macOS 26, a frame too on 27; FoundationModels weak-linked); JSON lines on stdout, exit 3 for unavailable. Built for arm64 with the newest SDK, deployment target macOS 13, each feature behind `#available`. `src-tauri/build.rs` builds it into `src-tauri/binaries/` (git-ignored); `tauri.conf.json` bundles it as the external binary `binaries/quadcam-intel` (`Contents/MacOS/`, beside `quadcam-cli`; `target/<profile>/` in a cargo build). Without Xcode 26 a stand-in answers unavailable; `QUADCAM_INTEL_REQUIRED=1` (CI, release) fails the build instead. `src-tauri/src/intel.rs` runs it through `modules::run::Runner` with a timeout (`intel/names.rs` its `suggest`, the request in a temp file); `gear::Env.intel` holds it. `core/ondevice.rs` is on-device suggestions: outings (day, place, aircraft) share the model's name with pack numbers, a field is filled only while empty or still the model's last value (`ClipPlan.ondevice`), the setting `on_device_suggestions`, and the session report's `summarize` |
| `src-tauri/src/schema.rs` | The MCP and CLI schema version (`SCHEMA_VERSION`), the deprecation table (`DEPRECATIONS`) and the surface guard's logic. `tests/it/surface.rs` runs the guard against `tests/surface/mcp.txt` and `cli.txt` |
| `src-tauri/src/modules/` | The module manager (`docs/modules.md`): `manifest.rs` (the pins in `src-tauri/resources/modules.toml`, compiled in; newer pins from a release's `modules.json`, taken only with its `modules.json.sig` by the updater key, `Modules::check`), `fetch.rs` (`Fetch`, `/usr/bin/curl`; a cargo process reaches only 127.0.0.1 unless `QUADCAM_FETCH=real`), `install.rs` (checksum, unpack, quarantine, ad-hoc signature, `installed.json`), `run.rs` (hash check before a run, the child-process `Runner`). `core/modules.rs` holds the `Core` methods |
| `scripts/notices.mjs` | Third-party notices (crates, npm packages, fonts, icons) and the license allow list; `pnpm build` writes `app/dist/THIRD_PARTY_NOTICES.txt`, which `tauri.conf.json` copies to `Contents/Resources`. `scripts/licenses/` holds SPDX standard texts |
| `src-tauri/Info.plist` | Photos, speech recognition and location usage strings, merged into the bundle's Info.plist |
| `src-tauri/Entitlements.plist` | Hardened-runtime entitlements (Photos library, location) for every signature |
| `src-tauri/tests/` | Integration tests on synthetic clips and FAT32 disk images. `it/` is one test binary, one module per area; the four files beside it change an environment variable and stay binaries of their own |
| `test-clips/` | Local test corpus. Git tracks only its README |
| `scripts/make-corpus.sh` | Builds `test-clips/synthetic/` |
| `scripts/dev-seed.py` | Fills a temporary `HOME` with a made-up library and gear for a dev build (`docs/development.md`, "Seed a dev HOME with made-up data") |
| `assets/icon.svg` | Icon source. Regenerate with `cargo tauri icon` |
| `docs/` | The user guide (linked from `README.md`), `docs/images/` (screenshots from `app/e2e/shots.spec.ts`), and `architecture-plan.md` |
